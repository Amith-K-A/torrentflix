# Fix TV series playback + unreliable autoplay

## Why TV series don't play (movies work)

1. **Torrentio's `fileIdx` is thrown away.** For TV, Torrentio usually returns *season-pack* torrents with `fileIdx` = the exact episode's file inside the torrent (documented in `src/lib/types.ts:24`). But `PlayerOverlay.tsx:149` POSTs only `{ magnet }`, and `startTorrent` (`src/lib/torrent-client.ts:120-135`) picks a file by generic scoring (browser-safe → video → **largest**). In a 10-episode pack that's an arbitrary episode — you click E5 and get a different file, or a sample.
2. **Auto-pick ignores codec/container.** Torrentio's TV sources are overwhelmingly x265/HEVC in `.mkv`; movies come from YTS as mp4/H.264. The auto-pick sort (`PlayerOverlay.tsx:120-125`) ranks only by seeds + quality, so a heavily-seeded HEVC/MKV pack is picked first and the browser can't decode it → black screen.
3. **No `onError` on `<video>`** — when decode fails the user gets zero feedback (no error, `playing` starts `true`, spinner starts off). It just looks dead: "not playable".
4. **"Play S1 E1" button doesn't pass season/episode** (`WatchView.tsx:126-135`): player label renders "S undefined E undefined", and its saved progress lands on key `tv:ID:0:0` instead of `tv:ID:1:1` — resume from the button doesn't match resume from the episode list.

## Why autoplay sometimes needs an extra click (earlier issue)

Autoplay relies solely on the `autoPlay` attribute of an unmuted `<video>` that mounts up to ~30s after the "Stream Now" click (torrent search + swarm metadata). The click's user-activation is stale by then, so Safari/strict-Chrome block unmuted autoplay; the resume-seek in `onLoadedMetadata` can also abort the in-flight play. Nothing ever retries `play()`.

## Changes

**`src/lib/torrent-client.ts`** — `startTorrent(magnet, opts?: { fileIdx?, season?, episode? })`
- If `fileIdx` is a valid index into `torrent.files` and is a video file → use it directly (Torrentio's authoritative pick).
- Otherwise, episode-aware scoring: files matching the requested episode (`S01E05` / `1x05` / `Episode 5` patterns) rank above non-matching ones, then browser-safe container, then video, then size (current order as tiebreakers).

**`src/app/api/stream/start/route.ts`**
- Accept optional numeric `fileIdx`, `season`, `episode` from the POST body and pass them to `startTorrent`.

**`src/components/PlayerOverlay.tsx`**
- Start effect: POST `{ magnet, fileIdx: selected.fileIdx, season: target.season, episode: target.episode }`.
- Auto-pick sort: add a playability rank (new helper) — prefer mp4/webm/x264/h264 sources over x265/hevc/avi when both are seeded; if only HEVC exists it's still used (existing warning banner covers that case).
- Add `onError` on `<video>` → switch to the existing error card with a clear message ("Your browser can't decode this MKV/HEVC source — pick another quality"), plus a "Switch source" button that opens the existing quality picker.
- **Autoplay fix**: `tryPlay()` helper called when the video mounts, on `onCanPlay`, and on a new `onSeeked` (fixes resume-seek aborts). On `NotAllowedError` → retry muted (allowed everywhere) + show a small "Tap to unmute" pill; if even muted fails → big centered play-button overlay. Track `userPaused` ref so retries never override a deliberate pause. Initialize `playing` to `false` and `buffering` to `true` on mount so the UI reflects reality.

**`src/components/WatchView.tsx`**
- "Play S1 E1" button: pass `season: 1, episode: 1` for TV (fixes label, search params, and progress key consistency).

**`src/lib/utils.ts`**
- Add `playabilityRank(name)` helper (container/codec hints parsed from the torrent name) used by the auto-pick.
